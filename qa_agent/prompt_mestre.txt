A forma mais profissional de fazer isso não é começar dando controle total do computador para a IA. O melhor caminho é começar com Playwright + Python, porque o Playwright foi criado justamente para automação e testes end-to-end em navegadores, com suporte a Chromium, Firefox e WebKit, inclusive em Python. Ele também é aplicável a workflows de agentes de IA.

Minha opinião técnica

Você deve criar isso em 3 camadas:

Camada de automação QA
Usa Playwright para abrir o navegador, acessar o endpoint do Apps Script, clicar, preencher formulários, navegar, testar botões, validar textos, testar login e capturar erros.
Camada de coleta de evidências
Captura prints, logs do console, erros JavaScript, status HTTP, requisições com falha, tempo de carregamento e trace completo da navegação. O Playwright permite capturar console logs com page.on("console"), eventos de request/response da rede e traces com histórico visual, DOM snapshots, network requests, console logs e screenshots.
Camada de IA analista
A IA não precisa clicar diretamente em tudo no começo. Primeiro, ela recebe os logs e evidências estruturadas e gera um relatório profissional: o que funcionou, o que falhou, onde falhou, provável causa, severidade e prompt técnico para a IA Dev corrigir. Para isso, você pode usar function calling/tool calling, onde o modelo decide chamar ferramentas, seu código executa a ação localmente e devolve o resultado para o modelo interpretar.

Passo a passo prático
1. Criar um ambiente seguro de testes

Antes de automatizar, crie:

URL de teste do Web App.
Usuário e senha de teste.
Planilha de teste, não a planilha real do cliente.
Dados falsos para cadastro, formulário, login e simulação.
Backup do projeto antes de cada rodada.

Isso evita que o agente clique, cadastre, apague ou envie dados reais por acidente.

5. Criar o runner QA com Playwright

Exemplo base:

import os
import json
from datetime import datetime
from pathlib import Path
from dotenv import load_dotenv
from playwright.sync_api import sync_playwright

load_dotenv()

APP_URL = os.getenv("APP_URL")

REPORT_DIR = Path("reports")
SCREENSHOT_DIR = REPORT_DIR / "screenshots"
TRACE_DIR = REPORT_DIR / "traces"

REPORT_DIR.mkdir(exist_ok=True)
SCREENSHOT_DIR.mkdir(exist_ok=True)
TRACE_DIR.mkdir(exist_ok=True)

def run_qa_test():
    results = {
        "started_at": datetime.now().isoformat(),
        "app_url": APP_URL,
        "console_logs": [],
        "network_errors": [],
        "steps": [],
        "screenshots": [],
        "status": "running"
    }

    with sync_playwright() as p:
        browser = p.chromium.launch(headless=False)
        context = browser.new_context(
            viewport={"width": 1366, "height": 768},
            record_video_dir="reports/videos"
        )

        context.tracing.start(
            screenshots=True,
            snapshots=True,
            sources=True
        )

        page = context.new_page()

        page.on("console", lambda msg: results["console_logs"].append({
            "type": msg.type,
            "text": msg.text
        }))

        page.on("response", lambda response: (
            results["network_errors"].append({
                "url": response.url,
                "status": response.status
            }) if response.status >= 400 else None
        ))

        try:
            page.goto(APP_URL, wait_until="networkidle")

            screenshot_path = SCREENSHOT_DIR / "home.png"
            page.screenshot(path=str(screenshot_path), full_page=True)

            results["steps"].append({
                "step": "Acessar página inicial",
                "status": "passed",
                "evidence": str(screenshot_path)
            })

            results["screenshots"].append(str(screenshot_path))

            # Exemplo de validação simples
            if page.locator("body").count() > 0:
                results["steps"].append({
                    "step": "Validar carregamento do body",
                    "status": "passed"
                })
            else:
                results["steps"].append({
                    "step": "Validar carregamento do body",
                    "status": "failed",
                    "error": "Elemento body não encontrado"
                })

            results["status"] = "completed"

        except Exception as e:
            error_screenshot = SCREENSHOT_DIR / "error.png"
            page.screenshot(path=str(error_screenshot), full_page=True)

            results["status"] = "failed"
            results["error"] = str(e)
            results["screenshots"].append(str(error_screenshot))

        finally:
            trace_path = TRACE_DIR / "trace.zip"
            context.tracing.stop(path=str(trace_path))
            results["trace"] = str(trace_path)

            context.close()
            browser.close()

    report_path = REPORT_DIR / "qa_raw_report.json"
    report_path.write_text(
        json.dumps(results, indent=2, ensure_ascii=False),
        encoding="utf-8"
    )

    return results

if __name__ == "__main__":
    run_qa_test()

Esse primeiro MVP já abre o navegador, acessa seu endpoint, tira print, captura logs de console, captura respostas HTTP com erro e gera um JSON bruto. O Playwright também permite gravar vídeo do teste e salvar traces para depuração visual posterior.

A API da OpenAI permite conectar modelos a ferramentas externas por meio de tool/function calling; nesse fluxo, o modelo solicita uma ação, seu código executa localmente e devolve o resultado para o modelo continuar a análise.

7. Evolução: transformar em agente de verdade

Depois do MVP, você pode evoluir para um agente com ferramentas como:

open_url(url)
click(selector)
fill(selector, value)
wait_for_text(text)
take_screenshot(name)
get_console_logs()
get_network_errors()
generate_report()

A IA passaria a raciocinar:

Preciso testar o login.
Vou abrir a URL.
Vou procurar o campo de e-mail.
Vou preencher o usuário de teste.
Vou clicar em entrar.
Vou verificar se apareceu dashboard.
Se falhar, vou capturar print, console e rede.

Isso fica mais próximo de um agente QA autônomo. O OpenAI Agents SDK permite criar agentes que planejam, chamam ferramentas, mantêm estado e executam workflows multi-etapas; ele também suporta ferramentas locais, function tools e execução no ambiente controlado pela aplicação.

Cuidado importante

Não dê permissão ampla para o agente controlar WhatsApp, Gmail, contas reais, Meta Ads, banco de dados real ou área financeira. Para QA, use sempre ambiente de teste, usuário de teste, dados fake e permissões limitadas. A autonomia tem que ser progressiva.
